Use Case: Опублікування програми

Scenaries:
    1.Scenario: Успішна публікація програми тренером
    Given користувач має підтверджену роль тренер
    When він обирає видимість "public" та зберігає програму
    Then система успішно зберігає програму
    And додає її до глобального каталогу для інших користувачів

    2.Scenario: Заборона публікації для звичайного атлета
    Given користувач має базову роль атлет, але не є тренером
    When він намагається зберегти програму з видимістю "public"
    Then система відхиляє запит на створення
    And виводить повідомлення, що публічна видимість доступна лише тренерам
    But дозволяє зберегти цю програму з статусом "private"

Pacticipants: FrontEnd, ProgramController, ProgramService, DataBase
Actors: User

Use Case: Створення тренувальної програми

Scenaries:
    1.Scenario: Успішне створення програми користувачем
    Given користувач перебуває на сторінці створення і має заповнені дані програми
    When він натискає "Зберегти програму"
    Then система зберігає програму та її вкладені тренування

Pacticipants: FrontEnd, ProgramController, ProgramService, DataBase
Actors: User


Актори, що використовуються:
User - ініціатор процесу, який взаємодіє з клієнтською частиною системи.

Учасники, що використовуються:
Frontend  — клієнтський застосунок, що відображає UI, збирає дані та відправляє HTTP-запити.

ProgramController — контролер, що приймає мережеві запити  та передає їх на рівень бізнес-логіки.

ProgramService — сервіс, що містить основну бізнес-логіку (перевірка ролей, підготовка даних для оновлення).

DataBase — шар доступу до даних , що виконує вибірку та збереження змін у БД.
