Функціональні вимоги:

1) КОЛИ користувач закінчив підхід певної вправи, система ПОВИННА створити запис Workout_Session_Set для цього підходу.
2) КОЛИ тренер створює програму, ТО система ПОВИННА вказати trainer_id в Program.
3) КОЛИ користувач обирає нову роль, ТО система ПОВИННА створити запис у таблиці відповідної сутності
4) Система ПОВИННА гарантувати доступ користувача до його програми навіть якщо закінчилась підписка
5) Система ПОВИННА дозволяти користувачу одну й тільки одну програму в певний момент часу
6) Система ПОВИННА дозволяти користувачу оплатити підписку для іншого за номером телефону
7) КОЛИ атлет створює для себе програму, ТО програма ПОВИННА створити запис Program з вказаним athlete_id
8) ЯКЩО користувач не зміг доробити до кінця тренування, ТО система ПОВИННА зберегти Workout_Sesion з статусом "incomplete" з можливістю продовження у майбутньому
9) ЯКЩО користувач створює програму і позначає isPublic = true, ТО система ПОВИННА забезпечити видимість програми у глобальному каталозі

Не функціональні вимоги:

1) ЯКЩО пристрій втратить зв'язок із програмою під час тренування, ТО система ПОВИННА зберегти поле Workout_Session status зі значенням "incomplete"
2) ЯКЩО тренер захоче видалити програму, якою користуються атлети, ТО система ПОВИННА змінити статус Program на "archived" замість видалення
3) ЯКЩО у користувача закінчилась підписка, ТО система ПОВИННА заборонити починати Workout_Session
4) ЯКЩО користувач захоче запустити паралельний Workout_Session, ТО система ПОВИННА заборонити йому це та повідомити користувача про поточний Workout_Session
5) ПОКИ користувач має підписку з isPaid = false і дата payment_deadline ще не настала, система ПОВИННА гарантувати доступ користувача до можливостей застосунку
6) ЯКЩО deadline_payment у підписки настав, то система повинна блокувати доступ користувача до можливостей застосунку та виводити повідомлення про вимогу оплатити підписку
