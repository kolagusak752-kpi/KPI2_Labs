Функціональні вимоги:
Система ПОВИННА обмежувати користувача наявністю лише однієї активної тренувальної програми в будь-який момент часу.

КОЛИ атлет завершує підхід вправи, система ПОВИННА зберегти результати цього підходу в межах поточної сесії тренування.

КОЛИ користувач створює нову тренувальну програму, система ПОВИННА закріпити його як автора цієї програми.

КОЛИ користувач ввів усі вправи у програму та натискає створити, система ПОВИННА вивести користувачу повідомлення про вибір видимості програми.

КОЛИ користувач хоче зробити свою програму публічною, система ПОВИННА перевірити чи є користувач тренером.

КОЛИ користувач отримує нову роль, система ПОВИННА надати йому відповідні права та можливості у застосунку

КОЛИ користувач вводить дійсний номер телефону іншого зареєстрованого акаунта під час оплати, система ПОВИННА застосувати придбану підписку до профілю вказаного користувача.

КОЛИ користувач позначає програму як публічну, система ПОВИННА додати цю програму до глобального каталогу для доступу інших користувачів.

КОЛИ атлет відкриває історію минулих тренувань, система ПОВИННА відобразити список завершених сесій із деталізацією результатів (вага, підходи, повторення) для кожної виконаної вправи.

КОЛИ атлет переглядає свій поточний план тренувань, система ПОВИННА відобразити запланований перелік тренувальних днів та закріплених за ними вправ.

КОЛИ атлет ініціює перегляд власного прогресу, система ПОВИННА проаналізувати історію його тренувань та відобразити динаміку зміни робочої ваги для кожної вправи.

ПОКИ користувач має раніше закріплену за ним тренувальну програму, система ПОВИННА забезпечувати доступ до її перегляду незалежно від статусу підписки.

ПОКИ триває пільговий період оплати для акаунту користувача, система ПОВИННА надавати йому повний доступ до всіх функцій застосунку із попередженням про необхідність оплати.

ЯКЩО тренування переривається до його логічного завершення (через дію користувача або втрату з'єднання), ТО система ПОВИННА зберегти сесію з статусом "incomplete" із можливістю її продовження у майбутньому.

ЯКЩО тренер ініціює видалення програми, яку наразі використовують інші атлети, ТО система ПОВИННА перевести програму в статус "archived" замість її безповоротного видалення.

ЯКЩО користувач ініціює видалення своєї приватної програми, то система ПОВИННА повністю видалити її з бази даних

ЯКЩО атлет намагається розпочати нове тренування без активної підписки та поза межами пільгового періоду, ТО система ПОВИННА заблокувати цю дію та перенаправити його на екран оплати.

ЯКЩО атлет намагається розпочати нове тренування за наявності вже активної сесії на іншому пристрої, ТО система ПОВИННА відхилити запит та сповістити його про поточне активне тренування.

ЯКЩО атлет захоче мати тренування з тренером, то система ПОВИННА надати йому список тренерів, з якими атлет зможе зв'язатися

Нефункціональні вимоги:

Система ПОВИННА підтримувати 5000 одночасних тренувальних сесій

ПОКИ користувач не має зв'язку з мережею, система ПОВИННА локально на пристрої користувача зберігати дані про виконані вправи та підходи
