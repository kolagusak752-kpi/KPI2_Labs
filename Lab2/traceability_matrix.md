Вимоги:
Функціональні вимоги:

REQ1: КОЛИ атлет обирає тренувальну програму з каталогу та ініціює її додавання, система ПОВИННА закріпити цю програму за профілем користувача як поточну активну.

REQ2: Система ПОВИННА обмежувати атлета наявністю лише однієї активної тренувальної програми в будь-який момент часу.

REQ3: КОЛИ атлет завершує підхід вправи, система ПОВИННА зберегти результати цього підходу в межах поточної сесії тренування.

REQ4: КОЛИ користувач створює нову тренувальну програму, система ПОВИННА закріпити його як автора цієї програми.

REQ5: КОЛИ користувач ввів усі вправи у програму та натискає створити, система ПОВИННА вивести користувачу повідомлення про вибір видимості програми.

REQ6: КОЛИ користувач хоче зробити свою програму публічною, система ПОВИННА перевірити чи є користувач тренером.

REQ7: КОЛИ користувач отримує нову роль, система ПОВИННА надати йому відповідні права та можливості у застосунку.

REQ8: КОЛИ користувач вводить дійсний номер телефону іншого зареєстрованого акаунта під час оплати, система ПОВИННА застосувати придбану підписку до профілю вказаного користувача.

REQ9: КОЛИ тренер позначає програму як публічну, система ПОВИННА додати цю програму до глобального каталогу для доступу інших користувачів.

REQ10: КОЛИ атлет відкриває історію минулих тренувань, система ПОВИННА відобразити список завершених сесій із деталізацією результатів (вага, підходи, повторення) для кожної виконаної вправи.

REQ11: КОЛИ атлет переглядає свій поточний план тренувань, система ПОВИННА відобразити запланований перелік тренувальних днів та закріплених за ними вправ.

REQ12: КОЛИ атлет ініціює перегляд власного прогресу, система ПОВИННА проаналізувати історію його тренувань та відобразити динаміку зміни робочої ваги для кожної вправи.

REQ13: ПОКИ користувач має раніше закріплену за ним тренувальну програму, система ПОВИННА забезпечувати доступ до її перегляду незалежно від статусу підписки.

REQ14: ПОКИ триває пільговий період оплати (Grace-період) для акаунту користувача, система ПОВИННА надавати йому повний доступ до всіх функцій застосунку із попередженням про необхідність оплати.

REQ15: ЯКЩО атлет намагається розпочати нове тренування без активної підписки та поза межами пільгового періоду, ТО система ПОВИННА заблокувати цю дію та перенаправити його на екран оплати.

REQ16: ЯКЩО тренування переривається до його логічного завершення (через дію користувача або втрату з'єднання), ТО система ПОВИННА зберегти сесію як "незавершену" із можливістю її продовження у майбутньому.

REQ17: ЯКЩО тренер ініціює видалення програми, яку наразі використовують інші атлети, ТО система ПОВИННА перевести програму в статус "archived" замість її безповоротного видалення.

REQ18: ЯКЩО користувач ініціює видалення своєї приватної програми, то система ПОВИННА повністю видалити її з бази даних.

REQ19: ЯКЩО атлет намагається розпочати нове тренування за наявності вже активної сесії на іншому пристрої, ТО система ПОВИННА відхилити запит та сповістити його про поточне активне тренування.

REQ20: ЯКЩО атлет захоче мати тренування з тренером, то система ПОВИННА надати йому список тренерів, з якими атлет зможе зв'язатися.

Нефункціональні вимоги:

REQ21: Система ПОВИННА підтримувати 5000 одночасних тренувальних сесій.

REQ22: ПОКИ користувач не має зв'язку з мережею, система ПОВИННА локально на пристрої користувача зберігати дані про виконані вправи та підходи.
